# Video Generation Pipeline Architecture

This document describes the structure, data flow, and current status of the Remotion-based procedural video generation pipeline.

## 1. System Architecture

The project converts a simple Markdown story or script into a fully rendered, animated MP4 video using a multi-stage, data-driven pipeline.

**Tech Stack:**
- **Core Engine:** Remotion (React-based video rendering)
- **Language:** TypeScript
- **State Management/Validation:** Zod (for strict JSON schema parsing)
- **Orchestration:** Custom `director` modules with optional LLM integration (`@ai-sdk/openai`, `@ai-sdk/google`).

## 2. Pipeline Flow

The execution starts at `scripts/video.ts` and follows these 5 steps:

1. **Director Planning (`1/5`)**
   - **Input:** A Markdown file (e.g., `ma-o-ban-dao-son-tra.md`).
   - **Process:** The `Director` (either `heuristic` or `openai`/`gemini`) parses the markdown into a structured array of Scenes.
   - **Output:** A draft `DirectorPlan` which defines the narration, visual intent, and importantly, an `illustration` descriptor object (atmosphere, environment, emoji elements, animations) for each scene.

2. **Text-To-Speech (TTS) Generation (`2/5`)**
   - **Input:** The `narration` text of each scene.
   - **Process:** Sends text to the TTS Provider (e.g., local TTS or external API).
   - **Output:** Generates `.wav` audio files and a set of `captions` containing word-level timestamps (precise to the millisecond).

3. **Validation & Synchronization (`3/5`)**
   - **Process:** The `scene.captions` (timestamps) are injected back into the `RenderPlan`. Duration is calculated based on audio length plus lead-in/tail frames.
   - **Output:** `generated/<project>/scene-plan.json` (the master source of truth for rendering).

4. **Remotion Bundling (`4/5`)**
   - **Process:** Webpack/Esbuild bundles the React components inside `src/remotion` via `@remotion/bundler`.

5. **Rendering (`5/5`)**
   - **Input:** The bundled React app and `scene-plan.json`.
   - **Process:** Remotion Chromium headless browser renders the video frame-by-frame. 
   - **Output:** The final `output/final.mp4`.

## 3. Procedural Rendering Logic (The "Smart" Scenes)

To ensure the video is perfectly in sync with the storytelling without relying on expensive, slow, or inconsistent AI Image APIs, the project uses **Procedural React Rendering**.

**How `StoryIllustrationScene.tsx` works:**
- It is **Data-Driven**: It does NOT parse text directly. It simply reads the `scene.illustration` object generated by the Director.
- **Atmosphere & Environment**: Renders SVG/CSS backgrounds like `mountain`, `interior`, or `city`, and overlays procedural weather layers (`RainLayer`, `FogLayer`, `DustParticle`).
- **Progressive Element Syncing**: Reads the TTS `captions` array. When rendering elements (e.g., 👻, 🚗), it calculates the exact `startFrame` based on when the corresponding `triggerWord` is spoken in the audio. The element only fades in at that exact moment.

## 4. Folder Structure

```
├── director/
│   ├── index.ts              # Entry point for Director
│   ├── heuristic-director.ts # Regex/Rule-based scene planner (No LLM required)
│   ├── openai-director.ts    # GPT-based scene planner
│   ├── schema.ts             # Zod definitions (DirectorPlan, RenderPlan, Illustration)
│   └── progression.ts        # Scene transition & beat logic
├── scripts/
│   └── video.ts              # Main execution pipeline (CLI)
├── src/
│   ├── remotion/             # Remotion Entry & Root config
│   └── video/                
│       ├── VideoAgent.tsx    # Main Sequence Orchestrator
│       ├── SceneFrame.tsx    # Global scene wrapper (camera, layout)
│       └── scenes/           # React Components for each SceneType
│           └── StoryIllustrationScene.tsx  # The core procedural storytelling renderer
├── generated/                # Output dir for scene-plan.json and temporary assets
└── output/                   # Final rendered MP4 files
```

## 5. Current Status & Future Refactoring

**Current Status:**
- The pipeline is **clean and robust**. All legacy/broken image generation API calls (Pollinations/Imagen) have been removed.
- Audio-Visual synchronization is highly accurate thanks to `captions` word-level timing mapping to Remotion's `useCurrentFrame()`.
- The system gracefully handles generic storytelling via emoji silhouettes and CSS filters, making it infinitely scalable across contexts.

**Refactoring Opportunities:**
- **Extract Generic Layouts:** Move `GenericEnvironment` and `EmojiElement` out of `StoryIllustrationScene.tsx` into reusable shared components.
- **More Elements:** Expand the emoji silhouette library or replace emojis with SVG icon libraries (e.g., Lucide React) for a more professional corporate look.
- **Camera Paths:** Make the `panX` and `zoomFactor` dynamically configurable from the `storyboard.camera` schema rather than hardcoding them in the Scene component.
